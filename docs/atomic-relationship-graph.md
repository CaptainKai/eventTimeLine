# Atomic Relationship Graph

The atomic relationship graph is the new write path for parsed news events:

```text
news -> proto_events -> atomic_event_relationships -> relationship_summaries
```

Legacy canonical event tables remain read-only for old dashboards and APIs:

```text
events, event_news, event_relationships, stories, hypotheses
```

## Tables

- `atomic_event_relationships` stores directed proto-event edges.
- `relationship_summaries` stores rule-generated relationship cluster nodes.
- `relationship_summary_members` links summaries to member `proto_events`.
- `relationship_summary_edges` links summaries to atomic relationship edges.

## Commands

```bash
npm run migrate-atomic-graph
npm run rebuild-atomic-graph -- --full
npm run rebuild-atomic-graph -- --full --dry-run
npm run rebuild-atomic-graph -- --since 2026-01-01 --batch-size 500
```

`--limit`, `--since`, and `--batch-size` only control script execution scope. They do not create business-level limits for summary membership or candidate counts.

## APIs

- `GET /api/v1/atomic-relationships`
- `GET /api/v1/relationship-summaries`
- `GET /api/v1/relationship-summaries/:id/graph`

## Behavior

- New parsed proto-events no longer create canonical `events` rows.
- New relationships are computed between `proto_events` directly.
- A new proto-event first recalls matching `relationship_summaries`; if none match, it falls back to entity/action/location overlap within the configured time window.
- Summary titles and descriptions are generated by rules only. LLM enhancement and summary restructuring are intentionally not implemented.
