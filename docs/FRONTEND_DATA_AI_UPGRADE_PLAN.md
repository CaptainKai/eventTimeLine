# 数据与 AI 前端升级执行计划

## 1. 升级目标

在保留现有原生 HTML、CSS、JavaScript Dashboard 的前提下，把 A05-A09 后端能力转化为可操作、可解释、可演示的“数据与 AI 工作台”。

升级完成后，前端需要回答五个问题：

1. 实时数据链路是否正常，数据新鲜度和质量如何。
2. 当前有哪些热点主题，趋势为何变化。
3. 用户能否使用关键词或语义方式检索新闻。
4. 一条结论来自哪些新闻、事件和处理版本。
5. Agent 调用了什么工具、使用了哪些参数、返回了哪些证据。

## 2. 设计原则

1. **不重写现有页面**：继续使用 `dashboard/public` 下的多页面结构和共享 API Client。
2. **先数据契约后视觉组件**：先稳定响应适配、错误态和证据元数据，再开发图表。
3. **业务视图与工程视图分离**：普通用户看搜索、趋势和关系；开发者看链路、版本和审计。
4. **所有 AI 结果必须可追溯**：展示 `source_ids`、`lineage_id`、`data_version` 和生成时间。
5. **渐进增强**：语义服务不可用时降级到关键词检索；图表失败不影响原始数据查看。
6. **避免虚假实时**：明确标识事件时间、处理时间、刷新时间和数据延迟。

## 3. 信息架构

新增一级导航“数据与 AI 工作台”，页面建议为 `data-ai-workbench.html`，内部使用四个 Tab：

| Tab | 面向对象 | 核心内容 | 后端接口 |
| --- | --- | --- | --- |
| 智能检索 | 分析人员 | 关键词/语义检索、过滤、命中解释 | `GET /api/v1/query/news` |
| 实时洞察 | 数据分析/运营 | 热点主题、小时趋势、来源质量 | `GET /api/v1/query/topics` |
| 血缘与图谱 | 数据工程/分析人员 | 新闻血缘、事件关系、版本信息 | `GET /api/v1/query/news/:id/lineage`、`GET /api/v1/query/graph/:id` |
| Agent 调试台 | AI 应用研发 | Tool 列表、参数表单、结果、证据和错误 | `GET /api/v1/agent/tools`、`POST /api/v1/agent/tools/:name` |

首页只增加三个轻量入口，不把所有工程信息塞入总览：

- 数据新鲜度与链路状态卡片。
- 热点主题 Top 5。
- “进入数据与 AI 工作台”入口。

## 4. 前端分层

```text
dashboard/public/
├── data-ai-workbench.html
├── scripts/
│   ├── utils/
│   │   ├── api.js                    # 新接口方法
│   │   ├── response-adapter.js       # 统一响应与错误适配
│   │   └── dashboard-shared.js       # 筛选、格式化、HTML 转义
│   ├── components/
│   │   ├── semantic-search.js
│   │   ├── topic-trend.js
│   │   ├── lineage-viewer.js
│   │   ├── agent-tool-console.js
│   │   └── pipeline-status.js
│   └── data-ai-workbench.js
└── data-ai-workbench.css
```

组件只依赖 `ApiClient` 和 DOM 容器，不直接互相调用。跨组件联动统一派发浏览器事件，例如 `workbench:news-selected`，避免形成页面级强耦合。

## 5. 基础任务

### F01：扩展 API Client

**工作内容**：

- 增加 `searchSemanticNews()`、`getTopicTrends()`、`getQueryLineage()`、`getQueryGraph()`。
- 增加 `getAgentTools()` 和 `executeAgentTool()`。
- 支持 `AbortController`、请求超时和主动取消旧搜索。

**验收**：每个方法正确生成 URL、Query 参数和 JSON Body；4xx/5xx 转换为统一错误对象。

**依赖**：无。

### F02：统一查询响应适配器

**工作内容**：

- 统一读取 `data`、`data_version`、`generated_at`、`source_ids`、`lineage_id`。
- 区分空结果、服务降级、超时、参数错误和服务异常。
- 对缺失可选字段提供安全默认值。

**验收**：正常、空数据、降级和错误 Fixture 均能稳定转换，页面不直接解析后端原始结构。

**依赖**：F01。

### F03：建立工作台页面骨架

**工作内容**：

- 新增页面、导航入口、Tab、加载骨架、空态和错误态。
- 复用现有 `nav-bar`、`section-card`、`chip` 等视觉语言。
- 支持 URL 参数保存当前 Tab、查询词和已选择新闻。

**验收**：桌面端和 1280px 宽度可用；刷新后页面状态可以恢复。

**依赖**：无，可与 F01 并行。

### F04：证据与版本公共组件

**工作内容**：

- 展示数据版本、生成时间、来源数量和血缘 ID。
- 提供复制 `source_ids`、跳转血缘视图和查看原始 JSON 的操作。
- 对陈旧数据和降级结果显示醒目标记。

**验收**：所有检索及 Agent 结果使用同一组件，不允许只展示自然语言结论。

**依赖**：F02、F03。

### F05：可测试的组件边界

**工作内容**：

- 将格式化、参数构建、响应适配和状态转换设计为纯函数。
- 为 DOM 组件提供可注入 API Client。
- 增加固定 Fixture，禁止单元测试依赖真实数据库和 LLM。

**验收**：核心纯函数和 API Client 可在 Node Test Runner 中执行。

**依赖**：F01-F04。

## 6. 高级任务

### U01：智能检索面板

**依赖**：F01-F05。

**工作内容**：

- 支持查询词、关键词/语义模式、来源、语言、时间范围和返回数量。
- 输入防抖 300-500ms；新查询取消旧请求。
- 结果展示标题、摘要、来源、发布时间、相关度和检索模式。
- 选择结果后联动血缘与图谱 Tab。
- 语义服务降级时明确显示“关键词降级”，不能伪装为语义命中。

**验收**：搜索、取消、空结果、超时、降级和分页场景均可操作。

### U02：实时洞察面板

**依赖**：F01-F05。

**工作内容**：

- 展示热点主题排行、小时窗口、新闻量和趋势变化。
- 标注窗口起止时间、最新数据时间和刷新时间。
- 支持来源和时间范围过滤，并可点击主题进入智能检索。
- 第一版使用原生 SVG/CSS 图表，避免增加大型图表依赖。

**验收**：自动刷新不会重复创建定时器；无数据窗口和延迟窗口有明确状态。

### U03：血缘与关系图谱面板

**依赖**：F01-F05、U01。

**工作内容**：

- 按“新闻 → 原子事件 → 标准事件 → 关系/摘要”展示血缘。
- 展示 parser、prompt、normalization、logic 等版本字段。
- 关系图支持节点选择、邻接信息和证据来源列表。
- 大图默认限制节点数，提供继续加载而不是一次性渲染全部节点。

**验收**：从检索结果能一键定位血缘；不存在的 ID、孤立节点和部分血缘可正确展示。

### U04：Agent Tool 调试台

**依赖**：F01-F05、U01-U03。

**工作内容**：

- 根据 Tool Definition 动态生成工具选择器和参数表单。
- 执行前展示请求预览；执行后分区展示业务数据、证据元数据、耗时和原始 JSON。
- 对未知参数、超限时间范围、超限条数和服务失败显示可操作错误。
- 支持把 Tool 返回的新闻或图谱结果发送到对应 Tab 查看。

**验收**：五个 Agent Tool 均可从 UI 调用；失败调用不会清空上一次成功结果。

### U05：首页升级摘要

**依赖**：U01、U02。

**工作内容**：

- 增加热点主题、数据更新时间和链路状态摘要。
- 首页只请求轻量数据，详细信息跳转工作台。
- 新接口失败时保持旧总览可用。

**验收**：关闭 A05-A09 服务时旧首页无功能回归；新卡片独立显示不可用状态。

### U06：端到端联动

**依赖**：U01-U05。

**工作内容**：

- 打通“主题 → 检索 → 新闻 → 血缘 → 图谱 → Agent 报告上下文”。
- URL 保存关键选择，支持刷新、复制链接和浏览器前进后退。
- 对每次 Tool 调用生成并透传 `x-request-id`，便于关联后端审计。

**验收**：一条完整分析路径不需要手工复制新闻 ID；后端审计可按 request ID 查到调用记录。

## 7. 推荐实施顺序

| 阶段 | 任务 | 可演示结果 |
| --- | --- | --- |
| P1 接口底座 | F01-F05 | 新接口可稳定调用，错误和证据元数据统一展示 |
| P2 最小工作台 | U01、U03 | 可以搜索新闻并追踪完整血缘 |
| P3 实时与 Agent | U02、U04 | 可以查看趋势并从 UI 调用 Agent Tool |
| P4 全链路联动 | U05、U06 | 首页入口和完整分析路径可演示 |

建议先完成 P1+P2，形成第一个可用版本；U02 的实时图表和 U04 的动态表单可并行开发。

## 8. 测试计划

### 8.1 单元测试

- API 参数序列化、超时、取消和错误转换。
- Response Adapter 对完整、缺失、空、降级和错误响应的处理。
- 日期、相关度、数据版本和证据字段格式化。
- Agent Tool Definition 到表单字段的映射。
- 图谱节点、边和血缘层级转换。

### 8.2 API 契约测试

- 使用固定响应 Fixture 校验前端所需字段。
- 对 `/query/*` 和 `/agent/tools/*` 做运行态冒烟。
- 后端新增字段允许兼容，删除或改变既有字段必须使测试失败。

### 8.3 浏览器测试

- 页面加载、Tab 切换、搜索、过滤、选择新闻、查看血缘和执行 Tool。
- 慢请求、重复点击、请求取消、断网、500、空数据和 HTML 注入文本。
- 1280px、1440px 和窄屏下的布局与滚动。

### 8.4 回归测试

- 现有情报总览、新闻解析台、标准事件台、关系与叙事台、知识图谱页面保持可用。
- 全局筛选和导航参数不被新工作台破坏。
- 新接口不可用时，旧页面不受影响。

## 9. 验收指标

| 指标 | 目标 |
| --- | --- |
| 首次可交互时间 | 本地开发环境小于 2 秒，不包含后端冷启动 |
| 搜索交互反馈 | 请求发出后 100ms 内出现加载状态 |
| UI 未处理异常 | 0 |
| AI 结果证据展示率 | 100% |
| Agent Tool UI 覆盖率 | 5/5 |
| 核心分析链路 | 主题到报告上下文可完整走通 |
| 旧页面回归 | 现有核心功能无失败 |

## 10. 风险与控制

- **Flink 未实际运行**：使用 PostgreSQL Serving 表 Fixture 开发，页面明确展示数据时间，禁止伪造实时更新。
- **Embedding 服务不可用**：保留关键词降级，并展示实际检索模式。
- **图谱数据量过大**：限制初始节点和边数量，按需展开。
- **接口结构继续变化**：所有页面只依赖 Response Adapter，不直接读取原始响应。
- **原生 JavaScript 复杂度上升**：坚持独立组件和事件通信；当前阶段不引入 React/Vue 重写风险。
- **Agent 输出不可信**：业务结果与证据元数据分区展示，原始 JSON 可审查。

## 11. 完成定义

前端升级只有同时满足以下条件才算完成：

1. A05-A09 的核心能力都存在可见入口。
2. 智能检索、实时趋势、血缘图谱和 Agent Tool 可完成真实后端调用。
3. AI 结果都能看到数据版本、生成时间和证据来源。
4. 降级、超时、空数据和错误场景均有明确反馈。
5. 单元、契约、浏览器冒烟和旧页面回归测试全部通过。
6. 开发者日志记录接口约定、关键设计选择、测试结果和已知运行限制。
