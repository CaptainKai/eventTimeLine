# 数据与 AI 应用研发：面试官评分卡与备战清单

> 本文为升级前版本。最新面试话术、STAR 案例和量化证据请以 `docs/DATA_AI_INTERVIEW_PLAYBOOK_V2.md` 为准。

## 1. 面试官真正要验证什么

| 能力维度 | 面试官的判断问题 | 本项目可证明什么 | 风险 |
| --- | --- | --- | --- |
| 数据建模 | 能否定义事实粒度、维度、分层和口径 | 原子事件事实、实体/时间/来源维度、主题聚合 | 未采用标准数仓命名 |
| SQL 工程 | 能否写复杂查询并解释执行计划 | PostgreSQL CTE、JSONB、索引、关系聚合、迁移 | 需现场准备 2 个复杂 SQL 案例 |
| 数据质量 | 是否理解幂等、重复、迟到、回填和审计 | Upsert、状态、审核、一致性检查、重建 | 缺完整质量指标看板 |
| 大数据 | 是否真实使用 Hive/Spark/Flink | 可讲迁移设计和概念映射 | 不能冒充生产经验 |
| LLM 工程 | 是否超越“调 API” | Prompt 分工、结构化输出、校验、重试、降级 | 缺系统化离线评测 |
| RAG | 是否理解检索、重排、引用和评测 | 知识单元、元数据、关系扩展、来源追溯 | 尚无完整向量链路 |
| Agent | 是否理解规划、工具、状态和护栏 | API、脚本和查询能力可封装为 Tool | 尚无正式 Agent Runtime |
| 知识图谱 | 是否理解节点、边、实体对齐和图查询 | 原子事件、Summary、成员、多类关系 | 非专用图数据库 |
| 工程能力 | 是否能定位问题并稳定交付 | Worker、DB Queue、重试、dry-run、测试 | 需准备故障案例与数据 |
| 表达能力 | 能否区分事实、权衡和下一步 | 架构演进和明确边界 | 避免堆砌术语 |

## 2. 推荐答题结构

任何项目题都按五步回答：

1. 业务问题：为什么要做，原方案哪里不行。
2. 数据粒度：输入、输出、主键、事实和维度是什么。
3. 技术方案：关键链路和核心取舍。
4. 可信机制：质量、幂等、失败、回填、审计。
5. 结果与反思：用可验证指标说明，并主动说清短板。

## 3. 能力证明材料

面试前准备一个本地演示或截图包，顺序如下：

1. 展示一条 `news` 原文和来源字段。
2. 展示该新闻解析出的多个 `proto_events`。
3. 展示实体或动作归一化结果与置信度。
4. 展示 proto 进入 batch assignment queue。
5. 展示所属 summary 和原子关系边。
6. 调用 graph/lineage API 展示结果追溯。
7. 制造或展示一个失败任务，执行 reset/resume 后恢复。
8. 展示一致性检查和重复数据审计结果。

## 4. 必备 SQL 题准备

至少能现场写出并解释：

- 按天、来源统计新闻量、解析成功率和平均原子事件数。
- 查询某实体 7 天内关联事件及其来源新闻。
- 找出无 summary 归属的 proto 和长时间 running 的任务。
- 使用窗口函数找每个主题置信度最高的 Top-N 事件。
- 递归或多次 Join 查询事件的一跳、二跳关系。
- 解释联合索引字段顺序、部分索引和 `EXPLAIN ANALYZE`。

## 5. 诚实边界

以下说法可以讲：

- “项目具有 ODS/DWD/DWS/ADS 类似的分层思想。”
- “我在 PostgreSQL 上实现了中小规模数据链路和 Serving 层。”
- “项目已具备 RAG 知识底座，但向量检索与评测还在下一阶段。”
- “已有工具能力和可信数据上下文，可继续封装为 Data Agent Skill。”
- “我理解 Spark/Flink 迁移方案，但这个项目没有生产使用它们。”

以下说法不要讲：

- “我建设了 Hive/Spark/Flink 生产数仓。”
- “这是完整自主决策 Data Agent。”
- “已经完成企业级 RAG。”
- “抽取准确率 90%+”——除非有标注集和计算脚本。
- “百万级、毫秒级、提升几十倍”——除非能展示数据库统计、日志和执行计划。

## 6. 七天补强计划

| 天数 | 任务 | 产出 |
| --- | --- | --- |
| Day 1 | 补项目数据字典与分层图 | 表粒度、主键、维度、口径文档 |

| Day 3 | 制作 50-100 条事件抽取 Golden Set | 标注 JSONL 与评测脚本 |
| Day 4 | 增加 BM25/Embedding 混合检索 Demo | 可运行 RAG 检索接口 |
| Day 5 | 将 3 个 API 封装为 Agent Tools | Tool Schema、参数校验、审计日志 |
| Day 6 | 写 Spark/Flink 迁移设计 | 架构图、Exactly-once 与回放说明 |
| Day 7 | 录制 5 分钟 Demo 并模拟追问 | 演示视频、问答复盘 |

## 7. 反问面试官

- 目前 Data Agent 的主要输入是指标元数据、SQL、文档，还是历史分析案例？
- 知识库的权威口径由谁维护，是否已有指标平台和字段级血缘？
- Agent 当前最大的瓶颈是召回、SQL 正确率、执行安全，还是业务接受度？
- 团队如何评估 Agent：任务成功率、SQL 准确率、引用完整性还是人工采纳率？
- 实时链路与离线数仓分别使用哪些引擎，Flink 与 Spark 的职责如何划分？
- 新人入职前三个月最希望交付的场景或指标是什么？
